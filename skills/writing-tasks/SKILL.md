# Writing tasks

- A title says what to do, and starts with a verb: "Send the signed lease to the landlord", not
  "Lease". It names the thing and the person or place it concerns, so it makes sense alone in a
  list a week later.
- Keep the user's own words where they gave them, in the language they wrote in.
- The summary is the one line the user scans: where the work stands and the next step. Leave it
  empty when the title already says it.
- Context holds what someone needs to start without asking: why it matters, what is known, what
  done looks like. A few lines are usually enough. Leave out what the source already holds.
- One task per piece of work someone can finish. When a request holds several, add several tasks
  rather than a list inside one.
- For an item from an email, a chat or a ticket, the title says what to do about it, not its
  subject line.
