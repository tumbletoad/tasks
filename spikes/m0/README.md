# The M0 spike kit

Lab code for the real-machine lab of A7 3.7. It is never shipped, never imported by a package (`spikes-never-imported` in `.dependency-cruiser.cjs`) and thrown away after M0. Results are kept outside the repository: a result that drives a design choice is stated in the specification section that uses it (A7 3.7).

The kit exercises the real OS mechanisms (Unix sockets, named pipes, the HMAC handshake, loopback HTTP and WebSocket, process spawning and process groups, owner-only modes and ACLs) at spike level. It is not the protocol. `kit.test.ts` is its self-test (`[A7.3.7.m0-kit.self-test]`), which runs on both CI runners.

## Rules

- Every command writes only under the folders you pass: `--state`, `--work`, `--log-dir`, the tree's base. Nothing writes to `~/Tasks`, `~/.tasks`, a real agent home or the registry. Two exceptions: the probe's `--markers` (P-2 of A2 3.5), which writes marker files to `%APPDATA%\tasks-m0\`, `%LOCALAPPDATA%\tasks-m0\`, `%USERPROFILE%\.tasks-m0\` and `%TEMP%`, by design (remove them the same day), and on Linux the service's socket folder `/run/user/<uid>/tasks-<install>/` (see `--socket-dir`), which is tmpfs and gone at logout.
- Fixture text only (space Mira, reference prefix M). The service's `events.jsonl` holds kinds, methods, routes and statuses, and the probe's log holds closed, structured records only (below). Never tokens, codes, tickets (only a 12-hex hash), briefs, tool arguments, command lines, raw paths or task text. Do not commit raw logs from a Linux lab run.
- The probe's log is safe for fixture input, not for arbitrary input. Three limits remain by design. An allow-listed identifier (`TASKS_TASK`, a session or thread ID and so on) and a package or executable name are logged as they are, so never put a secret in one. The `tree` key comes from the container's `tree.json`, so use the tree `kit tree` generated, unchanged. A hash in the log is a fingerprint for comparison, not anonymisation: a short value can be recovered from it.
- The Windows permission check refuses a folder or key whose access list holds a conditional or callback entry, because it cannot evaluate one. It reports that it cannot inspect the item and the service does not start.
- Registering the probe or the forwarder in an agent app goes into a scratch home (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`) with a key-level before and after record, removed the same day (A7 3.7 lab rules).
- The service refuses (exit 64) a state folder, socket folder or `ipc.key` that another principal can open: on Unix another owner, a group- or world-writable folder or a key with any group or other bit; on Windows an owner or any allow entry for a principal other than you, SYSTEM and Administrators. A state folder the service creates, and its key, get a user-only ACL on Windows (icacls), and later starts accept them. Where the Codex CLI's Windows sandbox is set up, `%TEMP%` and `%LOCALAPPDATA%` grant its group (CodexSandboxUsers) access, so a folder you create there yourself is refused. **Let the kit create its state folder:** pass a `--state` path that does not exist yet.
- On Windows the check reads the owner and DACL as SDDL, by SID, through Windows PowerShell calling .NET only, with an environment built from scratch. It works the same from Git Bash, PowerShell 7, cmd and a service. When the check itself cannot run (PowerShell missing or blocked, an unreadable item), the service exits 71 with `Cannot inspect permissions: <reason>`. That is not a verdict on the folder.

## Running it

Node 26.13.1 runs TypeScript directly. A system Node may be another version, so go through pnpm:

```
pnpm exec node spikes/m0/kit/kit.ts help
pnpm exec node spikes/m0/kit/kit.ts build <out>      # standalone .mjs copy and build.json, no node_modules
node <out>/kit.mjs help                              # the same commands from the copy
```

Run the forwarder, the shims and the probe from the built copy. Running `.ts` adds about 20 ms of type stripping at start (measured on Windows 11), which would bias B01 and B07. The copy can be moved to a Linux machine as it is.

| Command | What it does |
|---|---|
| `kit service --state <dir> [--port <n>] [--socket-dir auto\|run-user\|state] [--tree <container>] [--ui <built spike page>]` | The stand-in service. Checks the permissions above, takes the service lock (an exclusive SQLite transaction, A2 3.4; a second start exits 73), writes `ipc.key`, `service.json` and `events.jsonl`, and listens on a random named pipe (Windows) or a Unix socket and on `127.0.0.1`. The socket folder follows A2 3.2.1: `auto` uses `/run/user/<uid>/tasks-<install>/` when `/run/user/<uid>` exists and is private, else `<state>/run/`; `run-user` and `state` force one (`run-user` exits 64 when the folder is missing). `service.json` and `service/status` name it as `runtime`. A busy `--port` falls back to an OS-chosen port and sets `http.moved`. `--tree` names a `kit tree` container whose folders the page may reveal (default `<state>/scratch/`) |
| `kit call --state <dir> <method> [<json>]` | One rpc call after the handshake: `service/status`, `service/shutdown`, `ui/mint_code`, `spike.mint_ticket`, `spike.spawn {argv, cwd?, detached?, hidden?}` (the service starts a process without a shell), `spike.cancel_run {run}` (sends `cancel` to that run's shim), `spike.env_snapshot {tools?}` (E01: the agent environment the service builds by A4 3.8, from the login shell on Linux and the registry on Windows, and what its own inherited environment finds: counts, time and found or not found per tool, never a value or a path; `snapshot.ts`) |
| `kit open --state <dir> [--path <p>]` | Mints a UI code, verifies the listener with the HMAC probe (A2 3.8.4, 5 s deadline), prints `http://127.0.0.1:<port>/#k=<code>`. Hand the URL to `gio open`, `xdg-open` or `start`. The code works once, for 60 s |
| `kit ticket --state <dir> --cwd <dir> [--title <t>] [--run [--brief <text>]] -- <argv...>` | Mints a one-use launch ticket (120 s). With `--run` it is a run ticket for the run shim, which prints the run reference too. The brief goes to the agent's stdin and is never logged |
| `kit run-shim --state <dir> [--run-dir <dir>] [--grace <ms>] [--report-window <ms>] <ticket>` | The run shim, the same as `node run-shim.mjs` (below) |
| `kit tree <base>` | Builds the scratch tree in a new `mira-tree-*` folder under `<base>` and prints its paths: exact root, nested folder, git worktree, sibling clone, a Unicode-named repository and a punctuation-named folder |
| `kit bench --work <dir> [--runs 20] [--metric <m>] [--kit <dir>] [--cold]` | B01, B06 and B07: forwarder spawn to the first byte of the `initialize` reply with the service running (`forwarder_online`) and stopped (`forwarder_offline`), and shim spawn to its claim (`shim_claim`, stamped when the claim arrives, before any logging). Median, p95, max. Without `--kit` it builds into `<work>/kit-js`. `--cold` measures one `--metric` once, from a prebuilt `--kit` that this process has not loaded, and refuses a kit that is missing or older than its sources (it never builds) |
| `kit bridge --work <dir> --out <dir> [--rows B01,B02,B03,B04] [--label <l>] [--role <r>] [--kit <dir>] [--repeat <n>]` | B01-B07 with a result file per row (`bridge-bench.ts`, step M0.06). `B01` runs the bench above and writes B01, B06 and B07 (`--runs`, default 20; with `--cold --metric <m> --kit <copy>` one first-run file instead). `B02`: one forwarder, `--calls` (10), `--idle-ms` (60000), then its memory. `B03`: `--bridges` (10) at once with `--bridge-calls` (100) `status` calls each, and B05 from the same burst. `B04`: `--direct-calls` (500) through a forwarder and through a direct socket client, alternating. The service runs as its own `kit.mjs service` process on a new state folder per row, the forwarders as `node forwarder.mjs` from the same kit, both on the Node that runs the command. Memory is read from outside: Linux `/proc/<pid>/smaps_rollup` (USS, PSS, RSS), Windows .NET through Windows PowerShell (Private Bytes, Working Set, private working set), no admin. `--node-flag <f>` (repeatable) and `--compile-cache <dir>` apply to the forwarders only (A2 3.7.7 rule 2). CPU use over `--quiet-ms` (3000) before each row is recorded with it. A verdict only when the run meets the row's counts; a smaller run says "not judged". `--repeat 20` is A2 3.7.7's "20 runs per metric, median and p95": B02, B03 (with B05) and B04 each run 20 times on fresh state folders, and one file per row (`<row>-<label>.json`) holds every run's values, their nearest-rank median and p95 across runs, and a verdict from the p95 across runs against the threshold (counts such as handshake failures must be 0 in every run). B01, B06 and B07 already take 20 starts per metric in one set and run once. Every forwarder, service process, socket and poller a row starts is stopped before the row returns, also when it fails (`[A7.3.7.m0-bridge-bench.cleanup]`). Empty `/run/user/<uid>/tasks-<install>/` folders of its state folders are removed after each row |
| `kit accounts` | S12: the machine's other interactive accounts |
| `node forwarder.mjs --state <dir> [--space <id>] [--instance <id>] [--app <name>] [--reconnect]` | The spike bridge, stdio to the socket or pipe in mcp mode. Connect and handshake each have a 5 s deadline. Offline, or against a silent endpoint, it answers from the stub (A2 3.7.4). `--reconnect` (M0.07, S08): when the service is down or goes away it retries after 0.5, 1, 2 and 5 s, then every 10 s, answers requests in flight with `connection_lost`, and binds again with the client's first `initialize` or `server/discover` as `mcp_init`. Without it the forwarder never retries, as lab run B measured it |
| `node shim.mjs --state <dir> <ticket>` | The stand-in interactive `tasks shim`: handshake, one claim, folder and executable checks, announce, run the agent with inherited stdio in the terminal's process group, report started, settled and exited. It retries a down or silent service for 30 s, each attempt bounded |
| `node run-shim.mjs --state <dir> [--run-dir <dir>] [--grace <ms>] [--report-window <ms>] <ticket>` | The stand-in run shim (A4 3.11): claims a run ticket, starts the agent detached as the leader of its own process group (Unix: setsid, so its group ID is its PID; Windows: own process group, no console), brief on stdin then closed, stdout to `stdout.jsonl` and stderr to `stderr.log` in the run folder (default `<state>/runs/<run>/`, with `meta.json` and `exit.json`). Reports `run.started` and `run.exited`. A `cancel` becomes SIGINT to the agent's group (Unix) or `taskkill /PID <pid> /T` without `/F` (Windows), then SIGKILL to the group or `taskkill /T /F` after `--grace` ms (default 10 s). A signal that reaches the shim itself goes to `shim-signals.log` and `run.signal`. When the service stops, the agent keeps running and the shim re-attaches every second (`run.attach`, bounded at 3 s like every report). After the agent exits, the shim writes `exit.json`, then waits up to `--report-window` ms (default 10 s) for its connection, or a client that attaches within the window, to take `run.exited`. Then it abandons every attach still in flight and exits 0. When no service took the report, it says so on stderr and `exit.json` is the record |
| `node probe.mjs --log-dir <dir> [--scratch-root <container>] [--markers]` | The probe MCP server (stdio). Writes closed, structured records to `probe-<pid>-<time>.jsonl` (`probe-log.ts`): all environment variable names; values only for the identifier allow-list (each entry names the row that needs it), `TASKS_TICKET` as a 12-hex hash; for cwd and the path variables (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `APPDATA`, `LOCALAPPDATA`, `USERPROFILE`, `TEMP`, `TMP`) never the path but `sha256` of the canonical absolute path, `inside_scratch`, `under_packages` and, inside the scratch root, the `tree` key of the folder (from the container's `tree.json`) or `null` with its `depth`; the parent's PID and executable name only; package identity (`TASKS_PACKAGE`, `SNAP_NAME`, `FLATPAK_ID`, the Windows package full name) through a strict character class; and per MCP request its method, era, protocol version, client name and client version as known labels. Anything outside the known lists is logged as `[other:<sha256 prefix> length <n>]`. A last-line redactor replaces any environment value outside the allow-list (4 characters or more, benign names such as `USERNAME` and `OS` excepted); the `end` record counts how often it fired, normally 0. `--scratch-root` (or `TASKS_M0_SCRATCH_ROOT`) is the `kit tree` container. Its instructions carry a `request_id` rule for A06 |

The browser page (`/`) runs its checks by itself and posts the results to the service, so they appear in `events.jsonl` as `page_report`: redeem, fragment removed, session after reload, style with and without the nonce, WebSocket echo, clipboard on the button, the four shortcuts of U04, and one Reveal button per known folder. Reveal is an authenticated API call that names the folder by index, never by path. The service opens it with `explorer.exe` on Windows and `gio open`, then `xdg-open`, on Linux, and records a `reveal` event. WebSocket upgrades apply the same `Sec-Fetch-Site` rule as `/api/*`.

The MCP stub follows the official schemas (`schema/2025-11-25` and `schema/2026-07-28` in modelcontextprotocol/modelcontextprotocol, checked 2026-11-12). Legacy `initialize` counter-offers 2025-11-25 for an unknown version. A 2026-07-28 request with an unsupported `_meta` version gets `-32022` with `data.supported` and `data.requested`, one without a version gets `-32602`: `server/discover`, and any request with a 2026-only `_meta` key (`protocolVersion`, `clientInfo`, `clientCapabilities`, `logLevel` under `io.modelcontextprotocol/`) or params field (`inputResponses`, `requestState`), so it is never answered as a legacy request. A supported version without `clientCapabilities` gets `-32602` too. A request with none of these markers stays legacy, with or without an earlier `initialize`. Every 2026-07-28 result carries `resultType: "complete"`, and `server/discover` and `tools/list` carry `ttlMs: 0` and `cacheScope: "private"`.
