# Lab run N: headless runs and their streams (M0.11)

Lab code for rows N01, N02, N03 and N05 of A7 3.7. Never shipped, never imported outside `spikes/`, thrown away after M0. Only its output survives: the fixtures in `fixtures/streams/`, their schema in `tests/stream-schema.ts` and their content check in `tests/stream-content.ts`. The sign-in rule it follows is lab run A's (A7 3.7's lab rules); what N03 decided is in A4 3.11.3 and 3.11.8. It uses lab run A's helpers: the removal rule (`../agents/scratch.ts`), facts-only error labels (`../agents/facts.ts`) and the clean spawner with its one cleanup path (`../agents/spawn.ts`: `track`, `endChild`, `endAll`, `installCleanup`).

| File | Part |
|---|---|
| `record.ts` | The recorder: starts one CLI with the clean spawner's environment, brief on stdin then closed, raw stdout and stderr byte for byte into `<scratch>/raw/` only. Records exit code, signal, timings, line structure (partial final line, CRLF, non-JSON lines) and the event keys (from the fixture schema only). Optionally cancels when a stdout line matches: Ctrl+C or Ctrl+Break through the helper, `taskkill /T` without `/F`, TerminateProcess, or SIGINT or SIGTERM to the Unix process group (the agent leads its own group, as the run shim starts it). After 10 s without exit it forces the tree (`taskkill /T /F`, SIGKILL to the group). It lists the agent's process tree before the cancel, what was left after exit, and sweeps what was left. The child is tracked by lab run A's cleanup path: an exit, a timeout, a spawn error (a missing executable) and the lab's SIGINT or SIGTERM all leave through it, and the timer never outlives the run |
| `console-ctrl.cs`, `helper.ts` | The console-attach helper of A4 L14, compiled into the scratch folder with the .NET Framework's `csc.exe`. `send <pid> c\|break` frees its own console, attaches to the agent's, reads the console's process list once and refuses when it holds a process that is not the agent, a descendant or the helper (exit 3) or when the list cannot be read or does not fit (exit 6), then sends the event. It cannot stop a process that attaches between the check and the broadcast, and the event goes to every process on the console. `run <exe> [args]` re-enables Ctrl+C and then starts the agent with the same stdio, passing its exit code on: a parent started with `CREATE_NEW_PROCESS_GROUP` (Node `detached: true`, Git Bash) makes every descendant ignore Ctrl+C. `list` prints every process (PID, parent PID, executable name, creation time). `selftest` runs the send decision on synthetic lists |
| `tree.ts` | Process lists (the helper on Windows, `/proc` on Linux), descendants and survivors. A process is identified by PID, executable name and start time, and the sweep lists again before each kill, so a reused PID is never taken for a survivor |
| `sanitise.ts` | The sanitiser and the field inventory, by the schema `tests/stream-schema.ts` (see `fixtures/streams/README.md`) |
| `publish.ts` | Builds and checks every output (streams, inventories, indexes) in a stage folder inside the scratch folder, and copies them to the destination only when all pass |
| `guard.ts` | The machine rules as code: Windows-only commands (`DESKTOP_ONLY`), Claude Code sessions and full access are refused on a non-Windows host before anything starts |
| `lab.ts` | The commands: `build-helper`, `n01`, `n02`, `n03`, `n03-detached` (the lab restarts itself detached, then Ctrl+C to each CLI started plainly and through `run`), `repeats` (Windows), `n02-laptop`, `n05`, `resanitise`, `keys`, `cleanup`. The console and the result files get fixed classes, counts, exit codes, timings, schema names and yes or no facts only; stderr, error events and MCP errors stay in the raw folder. Errors print a fixed class (`errorLabel`) |
| `fake-cli.ts`, `runs.test.ts` | Self-test with fake CLIs (`[A7.3.7.m0-runs.self-test]`); no test starts a real claude or codex. One case runs the lab itself against fake CLIs whose stderr, errors and events carry private-looking values, and checks that none reaches the console, the result files or the fixtures |

Run with the repository's Node on the Windows lab machine:

```
pnpm exec node spikes/m0/runs/lab.ts build-helper --scratch %USERPROFILE%\tasks-test\m0-11
pnpm exec node spikes/m0/runs/lab.ts n01 --scratch %USERPROFILE%\tasks-test\m0-11
pnpm exec node spikes/m0/runs/lab.ts n05 --scratch %USERPROFILE%\tasks-test\m0-11 --fixtures fixtures/streams
```

On the Linux lab machine, copy `kit/wire.ts`, `kit/mcp-stub.ts`, `kit/probe-log.ts`, `agents/{probe,spawn,clis,config-record,facts,scratch}.ts`, `runs/*.ts` (without the tests) and `tests/stream-content.ts` and `tests/stream-schema.ts` in the same layout, with a `package.json` of `{"type":"module"}`, and run `lab.ts n02-laptop` and `n05` with the packaged Node of the signed spike archive. The raw streams stay in that machine's scratch folder; only the sanitised fixtures, the inventory and the result file are copied back, after the checks on that machine.

Caps (`<scratch>/runs-ledger.json`): Windows 30 Claude Code and 25 Codex sessions, Linux no Claude Code, 8 Codex sessions of which at most 2 resumable. Claude Code runs on haiku with `--setting-sources project --strict-mcp-config`, Codex with `--ignore-user-config`, `model_reasoning_effort="low"` and `--ephemeral` unless the run must be resumable. `cleanup --remove 1` removes the one Claude Code transcript folder of the working folder (only when it holds only this run's session IDs) and the rollout files of this run's persisted Codex threads, found by file name.
